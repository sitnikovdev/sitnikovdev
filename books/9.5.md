## 9.5 How an Agent Is Fundamentally Different from a Scripted Bot

Both a bot and an agent can _"reason"_ before producing a response. The reasoning process itself does **not** make a system an agent.

The key difference is **where the next step comes from**.

A **bot** operates within a predefined workflow. Even if it has access to an action, such as calling a specific API, the condition for _when_ to call it is explicitly defined by a developer in the code. The bot does not go beyond that predefined script, regardless of the meaning or context of the user's message.

An **agent**, on the other hand, works differently. Between reasoning steps, it can **decide on its own to interact with an external source**. It does so not because the code contains a rule like:

> "If the user asks about X, call Y."

Instead, the model reasons that it lacks the information needed to proceed and **decides which source or tool to use to obtain it**.

That source could be:

- a knowledge base via **RAG**;
    
- an external **API**;
    
- a database;
    
- a tool or function;
    
- code execution;
    
- or any other available tool.
    

The key point is **not what the agent does**, but **who decides what to do next**.

> **In a scripted bot, the developer defines the decision logic. In an agent, choosing the next action is itself part of the model's reasoning process.**
