**A contested but important question: does this mean programming as a skill is dying?**

It's tempting to draw a straight line from "you can just describe what you want to a neural network" to "programming knowledge is no longer necessary." That's my own honest reaction, based on what I see in my own practice — and I'll say it plainly: I lean toward thinking the role of "developer who just writes code" is on its way out. Nobody needs a pair of hands that types out what's already been specified — that part is exactly what a model does faster now.

But I want to be upfront that this is a contested claim, not a settled fact. Plenty of experienced engineers and researchers argue the opposite: the more powerful AI tools become, the more valuable the skill of reading, understanding, and debugging code becomes — because otherwise there's no way to know whether what the model generated can actually be trusted. A generated MVP that compiles and runs on a demo is a different thing from a system that holds up under real load, and telling the two apart still requires exactly the kind of programming knowledge some people claim is becoming obsolete.

So the honest answer isn't "programming is dying" or "nothing has changed" — it's that the value is moving. It's shifting away from the mechanical act of producing code and toward the judgment to know when generated code can be trusted, when it can't, and why. That shift is what the rest of this book is really about.
