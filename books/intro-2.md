# A contested but important question: does this mean programming as a skill is dying?

It's tempting to draw a straight line here:

> "You can just describe what you want to a neural network" → "programming knowledge is no longer necessary."

That's my own honest reaction, based on what I see in my own practice. I'll say it plainly: **I lean toward thinking the role of "developer who just writes code" is on its way out.** Nobody needs a pair of hands that types out what's already been specified — that's exactly the part a model now does faster.

But I want to be upfront: **this is a contested claim, not a settled fact.**

Plenty of experienced engineers and researchers argue the opposite. Their case:

- The more powerful AI tools become, the more valuable it is to read, understand, and debug code
- Without that skill, there's no way to know whether the model's output can actually be trusted
- A generated MVP that compiles and runs in a demo is a different thing from a system that holds up under real load
- Telling the two apart still requires exactly the programming knowledge some people claim is becoming obsolete

So the honest answer isn't "programming is dying." It isn't "nothing has changed" either.

**The value is moving** — away from the mechanical act of producing code, toward the judgment to know when generated code can be trusted, when it can't, and why.

That shift is what the rest of this book is really about.
