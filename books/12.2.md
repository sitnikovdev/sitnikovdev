### 12.2 LangChain: An Agent as a Chain of Steps

Here's what that looks like in practice — my first experiment was a Hello-World project. The context was a Wikipedia article about Elon Musk, and the prompt instructed the model to summarize the text and produce two concrete facts from it.

**The pieces:**

1. **A prompt template** (`PromptTemplate`) — a template with a slot for the article text plus the instruction
2. **A model** (`llm`) — a wrapper around a specific LLM provider
3. **A chain** — the steps connected with LangChain's pipe syntax (LCEL, LangChain Expression Language)

python

```python
chain = prompt | llm
result = chain.invoke(input={"context": wiki_text})
```

> For a developer with a functional-programming background, that `|` operator should look familiar — it's function composition. The prompt's output becomes the LLM's input; the pipe just shows the direction data flows.

`invoke()` runs the whole chain in one call: the article text gets slotted into the prompt, the prompt goes to the model, and the model returns a summary with two facts.

**This is LangChain's basic building block** — step by step, left to right, no branching and no going back: just `prompt → model → result`. For simple tasks like summarizing a single text, that's enough.

The open question is what happens once a straight line isn't enough anymore — say, if after the summary the system needed to decide whether it should fetch more data before giving a final answer. That's the subject of the next section.
