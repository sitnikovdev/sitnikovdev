### 14.3 Observability: Logs, Metrics, and Cost in Tokens

Observing an LLM system rests on two different but complementary tools. **Metrics** are aggregated numbers over time: average tokens consumed, how response latency shifts, requests per hour. They're good for spotting a **trend** — for example, a sudden spike in token consumption on otherwise-identical requests almost always means one of two things: the prompt has grown larger than it needs to be, or the model has started generating longer, less focused answers — making every request more expensive.

**Logs** are records of each individual request: what the user asked, what the model answered, how many tokens it used, how long processing took. If a metric flags an anomaly, the log is where you go to find out exactly what happened.

A separate signal source is **user feedback**, and it's worth distinguishing two kinds. Explicit feedback — a user actually clicking thumbs up or down — is rare: most people never bother pressing the button. Far more common is **implicit feedback**: a user gets an answer and immediately rephrases the question — a reliable sign the first answer didn't land, even if nobody flagged it directly. Cases with negative feedback, explicit or implicit, are worth studying separately — that's usually where systemic problems surface, not in the averages.
